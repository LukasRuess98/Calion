# Code and configuration package — central thermal energy storage in a multi-feed-in district heating network (DHN-A)

**Paper (working title):** *Central thermal energy storage at an industrial prosumer site: value attribution,
hydraulic feasibility and foresight limits in a multi-feed-in district heating network* (submitted to *Energy*, Elsevier).
**Version:** 1.0.0 (2026-11-02) · **Licence:** MIT · **Citation:** see `CITATION.cff`.

This package contains the complete model code, the configurations of all runs reported in the paper, a synthetic
example data set and the anonymised documentation of model, data and results. It runs end to end on the synthetic
data. The operational data of the studied network are **not** included (see below); with them, the same commands
reproduce the paper.

## What the model does

* **Energy layer:** hourly MILP (Pyomo, HiGHS) of the existing plants, a heat pump on industrial waste heat
  (partner A), an electrode boiler (partner B) and a central thermal energy storage with temperature classes at site S.
  Objective: fuel, CO₂, taxes and levies, electricity at the day-ahead price.
* **Hydraulic layer:** calibrated meshed substitute network of DHN-A (node pressures, pump stations, plant mass flows).
  Mode E validates an energy-optimal schedule, Mode H adds hydraulic cuts until no limit is violated.
* **Studies:** 2³ factorial (TES, partner A, partner B) with Shapley attribution, sensitivities, rolling horizon with
  price and demand forecasts, hosting capacity in the south, pandapipes cross-check, break-even investment.

## Not included (by design)

* **Operational data of the network** (hourly measurements 2025, plant data, consumer and sector tables, load profiles):
  confidential, provided by the operator for the project only. The synthetic data in `data/synthetic/` have the same
  files, columns, units and time conventions (see `data/synthetic/README.md`).
* **Partner data** (partner A waste-heat availability) and the hourly **grid CO₂ factor** file: local, confidential.
* **Result time series** (`results/`): derived from the confidential data. All reported numbers are in
  `reports/central_tes/paper_tables.md` and `results_v2.md`.
* **Day-ahead prices 2025** (DE-LU): public, but not redistributed here. Source: energy-charts.info API
  (`/price?bzn=DE-LU`, data BNetzA | SMARD.de, CC BY 4.0); expected as `data/prices/raw_2025.json`
  (`unix_seconds`, `price`). The synthetic data set ships its own synthetic prices.
* Manuscript text and figures; anonymisation tools and name lists.

## Anonymisation

The network is called **DHN-A**, the operator "the operator", the industrial partners **partner A** and **partner B**,
the storage site **S**; stations are V01–V24. Plant codes in the code and in the paper:

| code | paper | plant |
|---|---|---|
| KWK | CHP | gas combined heat and power plant (main plant, pressure holder) |
| MVA | WH | waste incineration heat |
| GT | GT | gas turbine with heat recovery |
| BIO | BCHP | biomass CHP (must-run) |
| HW1 | GB | gas peak boiler (south) |

Every text file of this package was scanned for real names of city, network, operator, partners, plants, streets,
consumers and signals against the project's non-public term lists; result in `NAME_SCAN.txt`.

## Quick start (synthetic data, ≈ 1 min)

```bash
pip install -r requirements.txt                      # Python ≥ 3.10; HiGHS is installed with highspy
export CENTRAL_TES_CONFIG=configs/central_tes/synthetic.yaml
python -m pytest -o addopts="" tests/test_central_tes.py
python -m scripts.dhn_study.central_tes.run --config configs/central_tes/synthetic.yaml --scenario F111-H --variants A
python -m scripts.dhn_study.central_tes.synthetic_data --full   # optional: whole synthetic year 2025 instead of Jan–Feb
```

Results are written to `results/synthetic/`. **Synthetic results have no meaning for the studied network** and must not
be compared with the paper.

## Reproducing the paper (requires the confidential data)

Place the study data set in `data/dhn_a/` (schema as `data/synthetic/`) and the day-ahead prices in `data/prices/`.
Partner-A availability and the hourly grid-CO₂ factor are read as CSV files via `paths.partner_a_csv` and
`paths.grid_co2_csv` (schema as `data/synthetic/partner_a_2023.csv` and `grid_co2_2025.csv`), set in a local
configuration `configs/local/central_tes_local.yaml`. Then, with the default configuration `base.yaml`:

```bash
python -m scripts.dhn_study.central_tes.run --factorial          # 8 scenarios, Mode E + H, calibrations A, C, B
python -m scripts.dhn_study.central_tes.run --sensitivity <set>  # A1–A6, B2, B4, PR, PS, PG, AT, P, X, X4, XR
python -m scripts.dhn_study.central_tes.run --rh --rh-factorial --rh-tes --rh-at --rh-robust
python -m scripts.dhn_study.central_tes.run --rh-foresight --rh-forecast
python -m scripts.dhn_study.central_tes.validate_pandapipes      # needs pandapipes
python -m scripts.dhn_study.central_tes.economics
python -m scripts.dhn_study.central_tes.hosting
python -m scripts.dhn_study.central_tes.consolidate
python -m scripts.dhn_study.central_tes.paper_tables             # -> reports/central_tes/paper_tables.md
python -m scripts.dhn_study.central_tes.paper_figures            # figures 1–7
```

All entry points and run times: `scripts/dhn_study/central_tes/README.md`.

## Software

Tested with Python 3.11, numpy 2.4, pandas 2.3, pyomo 6.10, highspy 1.15 (HiGHS), scipy 1.17, pyarrow 26,
matplotlib 3.11, pytest 9.2. pandapipes is needed only for the cross-check (`validate_pandapipes`).
